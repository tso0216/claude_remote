## Slide 14 — Conditional Operations

§2.7 Instructions for Making Decisions

- Branch to a labeled instruction if a condition is true
  - Otherwise, continue sequentially
- beq rs, rt, L1
  - if (rs == rt) branch to instruction labeled L1;
- bne rs, rt, L1
  - if (rs != rt) branch to instruction labeled L1;
- j L1
  - unconditional jump to instruction labeled L1

## Slide 22 — Branch Instruction Design

- Why not blt, bge, etc?
- Hardware for <, ≥, … slower than =, ≠
  - Combining with branch involves more work per instruction, requiring a slower clock
  - All instructions penalized!
- beq and bne are the common case
- This is a good design compromise

## Slide 30 — Exercise 2 | Signed Shift Operations

Exercise 2 | Signed Shift Operations

Given two 8-bit signed two’s-complement values:

A = 1101 1000₂      B = 0101 0000₂

(a) Interpret A and B as signed decimal values. Then perform an arithmetic right shift of A by 2 bits. Give the binary and decimal results.

(b) Perform a logical left shift of B by 1 bit. Give the resulting 8-bit binary value and interpret it as a signed decimal value.

Answer

(a) A = −40, B = 80

Arithmetic right shift: 1101 1000₂ >> 2 = 1111 0110₂ = −10

(b) Logical left shift: 0101 0000₂ << 1 = 1010 0000₂

As an 8-bit signed value, 1010 0000₂ = −96.

Key Point: Arithmetic right shift preserves the sign bit; left shift represents ×2 only when no overflow occurs.


## Slide 31 — Exercise 3 | Conditional Execution Trace

Exercise 3 | Conditional Execution Trace

Assume:  $s0 = 15,  $s1 = 9,  $s2 = 4

(a) What value is stored in $t0? Is the beq branch taken?

(b) Which arithmetic instruction, add or sub, is executed?

(c) What is the final value of $s2?

slt  $t0, $s0, $s1

beq  $t0, $zero, L1

add  $s2, $s2, $s0

j    Exit

L1:  sub  $s2, $s2, $s1

Exit:

Answer

(a) 15 < 9 is false, so $t0 = 0. Since $t0 = $zero, beq is taken to L1.

(b) The branch skips add and transfers control to L1, so sub is executed.

(c) $s2 = 4 − 9 = −5.

Key Point: slt produces 0 or 1; a following branch can use that result to control program flow.


## Slide 32 — Exercise 4 | If–Else with Comparison

Exercise 4 | If–Else with Comparison

Assume:  a → $s0,  b → $s1,  x → $s2,  y → $s3

if (a < b)  x = x + y;     else  x = x − y;

(a) Use slt to evaluate a < b. What value represents true or false?

(b) Write the complete MIPS code using slt, a conditional branch, and j.

(c) If a = 7, b = 12, x = 20, and y = 5, determine the final value of x.

Answer

(a) slt  $t0, $s0, $s1     → $t0 = 1 if a < b; otherwise $t0 = 0.

(b) slt  $t0, $s0, $s1

beq  $t0, $zero, Else     ;     add  $s2, $s2, $s3

j    Exit     ;     Else: sub  $s2, $s2, $s3     ;     Exit:

(c) 7 < 12, so $t0 = 1 and the branch is not taken. x = 20 + 5 = 25.

Key Point: Relational conditions such as < can be built from slt plus conditional branches.

## Slide 34 — Exercise 5 | Array Loop Analysis — Answer

Exercise 5 | Array Loop Analysis — Answer

Answer

(a) i = 1 → offset = 1 × 4 = 4.

Address = 1000 + 4 = 1004;  $t1 = A[1] = 8.

(b) i = 1: load 8 → bne not taken → i becomes 2.
