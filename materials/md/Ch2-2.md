  - c.f. unsigned values: extend with 0s

  - +2: 0000 0010 => 0000 0000 0000 0010

## Slide 23 — Exercise 1 | Two’s-Complement Arithmetic

Exercise 1 | Two’s-Complement Arithmetic

Assume 8-bit two’s-complement representation.
Calculate:  10010110₂ + 10110101₂

(a) Convert both operands to signed decimal values.
(b) Perform the binary addition using 8 bits.
(c) Interpret the 8-bit result as a signed decimal integer.

Answer

- 10010110₂ = −106;   10110101₂ = −75
- (b)  10010110₂ + 10110101₂ = 1 01001011₂
         Keeping the lower 8 bits gives 01001011₂.
- (c)  01001011₂ = 75
Key Point: Two’s-complement addition uses ordinary binary addition, but signed overflow occurs when the true result is outside the representable range.


## Slide 24 — Exercise 2 | Representation & Sign Extension

Exercise 2 | Representation & Sign Extension

Consider the 8-bit bit pattern 11011010₂.

(a) Interpret it as both an unsigned integer and a two’s-complement signed integer.
(b) Extend it to 16 bits under both interpretations.
(c) Verify that each 16-bit result preserves the original numerical value.

Answer

- Unsigned: 11011010₂ = 218
- Signed: 11011010₂ = −38
- (b) Unsigned zero extension: 00000000 11011010₂
       Signed sign extension: 11111111 11011010₂
- (c) 00000000 11011010₂ = 218
       11111111 11011010₂ = −38
       Therefore, both extensions preserve the original value.
Key Point: The same bit pattern can represent different values. Zero extension is used for unsigned values, while sign extension preserves a two’s-complement signed value.


## Slide 25 — Exercise 3 | Decode a Machine Instruction

Exercise 3 | Decode a Machine Instruction

Given the 32-bit R-format machine instruction:
000000 10010 10011 01000 00000 100000₂
Assume $s2 = 18, $s3 = 19, $t0 = 8, and funct = 32 means add.
(a) Identify op, rs, rt, rd, shamt, and funct in decimal.
(b) Decode the complete MIPS assembly instruction.
(c) Convert the 32-bit machine instruction to hexadecimal.

Answer

- op = 0, rs = 18, rt = 19, rd = 8, shamt = 0, funct = 32
- (b) rs = $s2, rt = $s3, rd = $t0
       funct = 32 → add
       add $t0, $s2, $s3
- (c) 0000 0010 0101 0011 0100 0000 0010 0000₂
       = 02534020₁₆
Key Point: Decoding R-format machine code requires separating the six fields, interpreting register numbers and funct, then reconstructing the assembly instruction.

## Slide 27 — Exercise 5 | Integrated R/I-format Analysis

Exercise 5 | Integrated R/I-format Analysis

Compare:
add  $t0, $s1, $s2
addi $t0, $s1, −12
Assume $t0 = 8, $s1 = 17, $s2 = 18.
(a) Identify the instruction format and register roles for each instruction.
(b) Represent −12 as the 16-bit immediate field used by addi.
(c) Compare how the 32 bits are allocated in R-format and I-format, and explain why addi can encode a constant directly.

Answer

- add: R-format; rs = $s1, rt = $s2, rd = $t0
- addi: I-format; rs = $s1, rt = $t0, immediate = −12
- (b) +12 = 0000000000001100₂
       −12 = 1111111111110100₂
- (c) R-format: op(6) | rs(5) | rt(5) | rd(5) | shamt(5) | funct(6)
       I-format: op(6) | rs(5) | rt(5) | constant/address(16)
       I-format replaces rd, shamt, and funct with a 16-bit immediate field.
Key Point: R-format dedicates fields to register operations, while I-format uses a 16-bit field to encode an immediate constant or address offset directly in the instruction.
